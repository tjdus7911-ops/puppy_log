# 멍로드 모바일 앱 — 기획 정리 (IA · 기능 · 데이터 · 시나리오 · 우선순위 · 배포)

작성 2026-11-11 · 기준: 「모바일 앱 UI/UX 및 전체 기능 개발 기획」, 모바일 시안 6화면(홈·여행 계획·여행 기록·AI 여행 일기·발도장 지도·커뮤니티)
원칙: **차량 앱이 최우선.** 모바일 작업은 차량 빌드·시연을 건드리지 않는 별도 단위(브랜치/폴더)로 진행합니다.
범례: ✅ 웹에 이미 있음(로컬 저장) · 🎨 디자인만 · ⛔ 서버/플랫폼 필요

## 0. 현재 구현과 시안 비교 요약

웹(`web/`)의 휴대폰 레이아웃이 사실상 모바일 앱 프로토타입입니다. 대부분의 화면이 이미 있고, 서버가 없어 **모든 데이터가 이 기기(IndexedDB)에만** 저장됩니다.

| 시안 화면 | 현재 | 차이 |
|---|---|---|
| 홈 | ✅ 반려견 히어로·새 여행·최근 여행·발도장 요약 | 시안은 ‘진행 중인 여행’ 중심 홈(빠른 기능 4개·오늘의 사진). 여행지 활동 화면(`Destination`)에 이미 같은 구성 → 진행 중일 때 홈으로 승격 필요 |
| 여행 계획(1 계획 → 2 설정 → 3 확인) | ✅ 한 화면 5섹션 | 3단계 분리, 날짜 선택, **계획 저장(PLANNED)**, 방문 예정 장소, ‘차량으로 전송’ ⛔ |
| 여행 기록(앨범 상세) | ✅ 히어로·통계·앨범·경로·방문 장소 | 사진 순서 변경·대표 사진 지정은 커뮤니티 편집기에만 있음 → 앨범에도 적용 |
| AI 여행 일기 | ✅ 기록 기반 초안·수정·공유 카드 | 다시 만들기·임시 저장·커뮤니티 공유 버튼 정리 |
| 발도장 지도 | ✅ 실제/데모 구분·지역 목록 | 반려견별·연도별 필터 |
| 커뮤니티 | ✅ 피드·다크 상세·앨범 선택·편집·작성·완료·신고/차단(로컬) | 팔로잉·서버 피드 ⛔, 댓글 수정/삭제, 운영자 기능 ⛔ |
| 내 정보 | ✅ 반려견·통계·설정 | 차량 연결 관리 ⛔, 알림 설정, 내 게시글/저장/좋아요 목록, 탈퇴 ⛔ |

## 1. 모바일 전체 IA 및 화면 목록

```
하단 탭: 홈 · 여행 · 기록 · 커뮤니티 · 내 정보
홈
 ├─ (진행 중) 여행 히어로 → 빠른 기능(사진 추가·장소 기록·메모·발도장 지도) · 오늘의 사진 · 오늘의 기록 · 여행 메모 · 추천 동반 장소 · 여행 이어가기/마무리
 └─ (진행 없음) 반려견 프로필 · 새 여행 시작/계획 · 최근 여행 · 추천 여행지
여행
 ├─ 여행 계획 1/3 목적지 검색 → 2/3 반려견·휴식 설정·방문 예정 장소·날짜 → 3/3 확인·저장·차량으로 전송
 ├─ 저장된 계획 목록 · 진행 중인 여행(차량 상태 동기화)
 └─ 여행지 활동 기록(도착 알림 딥링크 대상)
기록
 ├─ 여행 앨범 목록 → 여행 상세(사진·경로·방문 장소·메모) → 전체 화면 뷰어
 ├─ AI 여행 일기(생성·수정·다시 만들기·저장·공유 카드)
 └─ 발도장 지도(전체/반려견별/연도별 → 지역 → 지역 앨범)
커뮤니티
 ├─ 피드(추천·최신·팔로잉·지역별) → 게시글 상세(전체 화면 미디어)
 └─ 작성 A(일반: 미디어→편집→글·장소·공개범위) / B(앨범 공유: 앨범→사진 선택→일기 포함 여부→글)
내 정보
 ├─ 내 반려견(추가·편집) · 내 여행(통계·앨범·발도장)
 ├─ 내 커뮤니티(작성·저장·좋아요한 글)
 └─ 설정(차량 연결·알림·개인정보·계정 탈퇴) · 알림함
```

## 4. 모바일 독립 사용 시나리오(차량 없음)

1. 가입 → 반려견 등록 → 여행 계획(목적지·날짜·반려견) 저장(PLANNED)
2. 출발할 때 ‘여행 시작’ → 휴대폰 GPS로 기록(웹의 device-location 모드와 동일) 또는 기록 없이 여행지 활동만
3. 도착 → 여행지 활동(사진·장소·메모) → 돌아가는 길(선택) → 여행 마무리 → AI 일기 → 앨범·발도장 → 커뮤니티 공유
→ 현재 웹 데모 시나리오(E2E 30단계)가 이 흐름을 이미 검증합니다(차량 대신 데모·기기 위치).

## 5. 목적지 도착 알림 시나리오

1. 차량 NaviHelper 도착 이벤트(⛔ 실제 연동 전: 웹은 GPS/데모 감지) → 차량 앱이 구간 저장, Trip → AT_DESTINATION
2. 이벤트를 **아웃박스에 저장**(✅) → 네트워크 가능 시 `POST /events`(멱등 키=이벤트 id)(✅ 클라이언트 / ⛔ 서버)
3. 서버: 같은 id 무시 → 사용자의 모바일 기기 토큰으로 FCM/APNs 발송(⛔)
   - 제목 “🐾 사슴이와 목적지에 도착했어요!” / 본문 “강릉 경포해변에 도착했어요. 오늘의 여행을 사진과 함께 기록해 보세요!”(✅ 문구 생성)
4. 알림 선택 → 딥링크 `mungroad://trip/{tripId}/activity` → 여행지 활동 기록 화면(“사슴이와 강릉 여행 · 지금 여행의 추억을 남겨보세요!”)
5. 예외: 알림 권한 없음 → 앱 내 알림함 · 오프라인 → 재연결 후 아웃박스 재전송 · 같은 도착 중복 금지 · 목적지 여러 곳은 구간별 이벤트 · 알림 끄기 설정 · 데모 도착은 전송하지 않음(✅ `skipped-demo`)

## 6. 커뮤니티 작성·탐색 플로우

- 탐색: 피드(추천·최신·팔로잉·지역별) → 카드 → 전체 화면 상세(스와이프) → 장소 태그 → ‘이곳으로 여행하기’(목적지 자동 입력 ✅)
- 작성 A: + → 앨범 선택(최대 10) → 편집(순서·크롭·필터·문구·메모) → 글·장소·해시태그·공개 범위·위치 공개 동의 → 게시 → 완료(실패 시 입력 유지 ✅)
- 작성 B: 여행 상세 ‘커뮤니티에 공유하기’ → 사진 자동 선택 → (🔜 AI 일기 일부 포함 여부) → 게시
- 개인정보: 전체 경로·출발지·집 위치 비공개, 좌표 소수 3자리, 사진 재인코딩으로 위치 메타데이터 제거
- 운영: 신고 접수·차단(✅ 로컬) / 운영자 검토 콘솔·제재·탈퇴 데이터 처리(⛔ 서버, 운영자 권한 분리)

## 설치형 앱(PWA) — 2026-11-12 결정
모바일 동반 앱은 지금 웹 앱을 설치형(PWA)으로 제공합니다. 차량 앱(Android Automotive, Pleos SDK)과 역할을 나눕니다(휴대폰: 여행지 기록·멍슐랭·여행 기록·커뮤니티).
- `web/public/manifest.webmanifest`: 이름·아이콘(일반·maskable·apple-touch)·시작 화면(`#/home`)·바로가기(여행 기록·커뮤니티)
- `web/src/pwa/sw-template.js` → 빌드 때 `dist/sw.js` 생성(vite 플러그인): 앱 파일 미리 저장, 화면 이동은 네트워크 우선·오프라인이면 저장본. 외부 API는 캐시하지 않음
- `web/src/pwa/install.ts`, `InstallCard.tsx`: 안드로이드·PC Chrome은 설치 창, 아이폰은 Safari '공유 → 홈 화면에 추가' 안내. 미리보기 iframe·HTTP 에서는 서비스 워커를 등록하지 않음
- 설치하려면 **HTTPS 로 배포된 주소**가 필요합니다(claude.ai 미리보기 안에서는 설치 불가). 저장소의 `vercel.json`·`netlify.toml` 또는 GitHub Pages 로 배포할 수 있어요.
